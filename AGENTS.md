## Evidence boundary

- Treat KPB visual rules in this repository as project-derived, not official enterprise-wide KBank policy.
- Treat current portfolio counts as supplied current baseline and stabilized counts as targets.
- Property Record is not Available Opportunity.
- Client interest is not owner consent or a completed introduction.
- KBank NPA, BAM, and other sources remain future/approved-source possibilities until confirmed.
- Never promote KPB-specific assumptions into the shared Landometer layer.

## Build rules

- Start from the client decision and emotional tension, not technology.
- Keep KPB visually and relationally primary; Landometer is the enabling layer.
- Preserve official assets and current typography fixes.
- Inspect the current repository and recent commits before replacing `styles.css`, `index.html`, or assets.
- Use illustrative data only in the public demo.
- Label simulated OTP and local matching as demonstration behavior.
- Keep hard constraints separate from fit scores.
- Show reason, counter-signal, freshness, permission/readiness, and next check for every candidate.
- Write Thai natively; do not mirror English sentence structure.
- Create real `.md` files, never `.md.txt`.

## Publish rules

- The public site is `https://montri-th.github.io/KPB-private-match/`.
- Publish only after explicit authorization.
- Verify the live URL and requested release markers before reporting success.
- Remove one-time publishing and verification workflows after they finish.
- Noindex is not access control.
